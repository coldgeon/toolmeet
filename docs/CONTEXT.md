# U-Solve 아이디어 배경과 과거 질문

이 문서는 아이디어의 출발점과 과거 피드백을 보존한다. **현재 프로토타입의 확정 기획은 [PLAN.md](PLAN.md), 상세 결정은 [PRODUCT.md](PRODUCT.md)를 따른다.** 아래의 초기 아이디어·기술 후보를 승인된 구현 명세로 취급하지 않는다.

## 아이디어의 출발점

사용자는 빠르게 쏟아지는 AI 소식 때문에 중요한 것을 놓치고 있다는 불안을 느꼈다. 자극적인 제목과 벤치마크, 실제 사용 후기 사이에서 자신이 배워야 할 것을 고르기 어렵다고 했다. 개인적으로 먼저 쓰고 싶으며 비슷한 사람이 많을지 시장성도 궁금해했다.

Threads에서 사람들의 실제 의견과 말투를 보고, 예상하지 못한 도구를 발견하는 경험을 중요하게 여긴다. SNS 글은 그 자리에서 읽기 쉽지만 다시 찾아 공부하거나 작업에 쓰기 어렵기 때문에 소식과 후기를 하나의 자료로 연결하고 저장·갱신하는 아이디어로 발전했다.

## 유지해야 할 요구사항

- 한국어 Threads가 핵심 소스다.
- Threads 자동 수집이 안 되면 핵심 가치가 크게 훼손된다는 입장이다.
- 키워드 검색만으로 수집하기보다 작성자와 인용·재게시·대화를 따라 새로운 정보를 발견하기를 원한다.
- 한 소식으로 중복을 묶고 핵심 설명 아래 실제 작성자의 글을 확인한다.
- 공식 문서와 실사용 후기를 비교하되 의견·측정 조건·미확인을 구분한다.
- 최신 정보가 들어오면 저장 당시의 설명에서 무엇이 달라졌는지 보여준다.
- 저장한 취향에 맞추되 관심 밖의 새로운 소식도 보여준다.
- 학습 계획과 실력 진단은 처음 제안됐지만 첫 버전 필수 기능으로 확정하지 않았다.

## 과제와 협업 피드백

- 과제는 일반 앱에 AI 에이전트를 더해 만족도나 생산성 향상을 시연하는 유형을 선택했다.
- 기획서는 시스템 목적, 에이전트 구성과 동작, 기존 대비 차이를 쉬운 문장으로 설명해야 한다.
- 제목 외 문장은 글머리 기호를 쓰고 한 항목에 한 문장을 적는 제출 참고 양식이 있다.
- 제출자는 내용을 이해하고 본인의 말로 직접 작성·설명해야 한다.
- 피드백은 박찬건·김성원 협업, AI 소식 정리와 업무용 도구 추천의 연결, 사용자 환경에서 사용 가능한지 확인하는 방향이다.
- 기획서 컨펌은 별도로 받지 않아도 된다는 안내와 10월 12일 22시 마감이 전달됐다.
- 두 사람 모두 백엔드를 희망하며 로그인·화면·배포·문서 등 부수 작업을 나누기를 원했다.
- 사용자는 이후 통합을 아직 검토 중이라고 정정했으므로 과거 협동 기획을 그대로 실행하면 안 된다.

## 기존에 만든 후보안

피드에서 소식 발견 → 업무와 환경 입력 → 도구 후보와 추천 이유 → 설치·비용·자료 전송 조건 확인 → 시작 안내 → 저장 및 갱신 흐름을 제안했다. 첫 시연 업무로 공개 소식의 주간 보고서와 표 자료 정리 보고서를 논의했지만 최신 범위 재검토 대상이다.

환경 적합성은 입력 조건과 일치, 조건 충족 필요, 확인 필요, 현재 조건과 불일치로 나누는 안이다. 문서상 지원과 실제 실행 확인은 분리해야 한다. 모르는 회사 정책을 허용으로 판단하거나 지원하지 않는 도구를 억지로 추천해서는 안 된다.

기술 후보는 TypeScript, Next.js, PostgreSQL, 작업 서버, 공통 근거 저장소다. 과거 모델명과 공급자·버전·비용은 최신 사실이나 필수 선택으로 보지 말고 구현 전 확인한다.

1. 이번 프로토타입의 중심은 실무자의 문서 업무 해결로 정했다. AI 소식 정리와의 독립·부분 연결·통합은 후속 결정이다.

3. 사용자는 기존 제품 코드·정리된 워크플로·협업자 별도 진행 작업이 없다고 확인했다. GitHub 원격 인증과 실행용 계정·공급자는 별개로 미확인이다.
4. 마감은 2026-10-12 22:00(Asia/Seoul) 전이고, 세 문서 사례의 본문→결과물 시연 목표와 사전 판정표는 정했다. 제품 실행은 아직 없고 추가 실제 파일 조합은 미정이다.
5. 한국어 Threads 자동 수집은 소식 안의 핵심 요구지만 이번 문서 시연의 통과 조건이 아니다. 실제 자동 수집이나 기업 환경의 실행 성공은 검증하지 않았다.

이미 확인된 선호를 반복해서 묻지 않는다. 사용자가 구현을 요청하면 [완료 기준](ACCEPTANCE.md)과 남은 파일·도구 결정을 확인해 Seed로 실행 범위를 만든다.
