# U-Solve 기업 업무 요청서 초안

담당자는 기술 이름을 몰라도 된다. **한 번에 자동화하고 싶은 업무 하나**를 기준으로 아래 항목을 작성한다. 모르는 항목은 `모름`으로 적고, U-Solve가 필요한 부분만 다시 묻는다. 첫 문의의 세 항목, 실제 문서를 나중에 요청하는 시점, 파일 첨부를 기본으로 하되 본문 붙여넣기도 받는 방식은 사용자와 확정했다. 파일별 지원 형식과 나머지 세부 문구는 인터뷰 중인 기획안이며 화면 구현은 아니다.

## 복사해서 작성할 요청 형식

```text
[첫 문의]
해결할 업무:
현재 처리 순서: 1)  2)  3)
원하는 결과와 반드시 포함할 항목:

[시뮬레이션 전 간단 확인 — 첫 문의 뒤에 요청]
원본의 저장 위치·형식과 원하는 결과 형식:
회사 정책상 외부 AI 사용 가능 여부(사전 정보, 실제 전송 허용 아님): 가능 / 불가 / 모름
현재 쓰는 서비스 종류와 새 도구 설치·연결 가능성(계정 정보 입력 아님):

[방향 승인 후 실제 시험 전 추가 자료]
대표 입력 문서: 제공 / 가린 문서 제공 / 아직 없음
입력 문서의 종류·개수와 전달 방법: PDF / Docs·Word / Excel·시트 / 기타; 파일 첨부 / 본문 붙여넣기
정해진 결과 양식 또는 필수 항목:
이번 문서를 선택한 도구·공급자에 전송하도록 허용하는지: 허용 / 불허 / 모름
이번 시험에 필요한 계정 연결·유료 호출을 허용하는지: 각각 허용 / 불허 / 해당 없음 / 모름
결과를 확인할 기준:

[반복 적용을 원할 때]
반복 빈도와 한 번에 처리할 문서 수:
현재 쓰는 도구와 설치·연결 가능 여부:
허용 비용과 필요한 시점:
결과를 최종 확인할 담당자:
```

첫 문의에는 위 세 줄만 작성하면 된다. U-Solve는 그다음 후보를 가르는 조건만 짧게 묻고 `모름`을 허용한다. 조건을 모르면 특정 도구의 추천·순위·시작 절차를 보류하고, 가정한 절차와 빈 예상 출력 형태만 시뮬레이션으로 보여준다. 공개 도구를 예시로 보여주더라도 회사 적합성 미판정이라고 표시한다. 담당자가 방향을 수정·승인한 뒤 실제 문서·양식·계정 권한과 실행 허용, 반복 적용 항목을 그 단계에 필요한 만큼 요청한다. 시뮬레이션은 실제 문서 처리 결과가 아니며 설계 승인은 자료 전송·계정 연결·유료 호출 허용이 아니다.

## 1. 첫 문의에 필요한 내용

| 항목 | 담당자에게 묻는 말 | 예시 |
|---|---|---|
| 해결할 업무 | 지금 어떤 일을 반복하거나 어렵게 처리하나요? | 회의록에서 결정 사항과 할 일을 따로 옮긴다. |
| 현재 방식 | 어떤 자료를 받아, 어떤 순서로 처리하고, 어디에 결과를 남기나요? | 회의록 파일을 읽고 표에 복사해 팀에 공유한다. |
| 원하는 결과 | 끝나면 어떤 결과물을 받아야 하나요? 꼭 들어갈 항목은 무엇인가요? | 결정 목록과 할 일·담당자·기한 표. |

이 세 항목으로 업무 명세 초안을 만들 수 있다. 이어서 원본 위치·형식, 목표 결과 형식, 회사 정책상 외부 전송 가능성, 기존 서비스와 설치·연결 제약 중 후보를 가르는 항목만 묻는다. 계정 정보나 실제 문서는 이때 요구하지 않는다. 답이 없어도 시뮬레이션은 가능하나 문서 본문이 없으면 실제 내용 처리나 특정 솔루션의 `그대로 사용 가능` 판정은 하지 않는다.

## 2. 실제 문서 처리 전에 필요한 내용

| 항목 | 담당자에게 묻는 말 | 필요한 이유 |
|---|---|---|
| 대표 입력 | 실제로 처리할 문서 또는 내용을 가린 대표 문서 1건 이상을 제공할 수 있나요? PDF·Docs/Word·Excel/시트 등 종류와 파일 형식을 알려주세요. 파일 첨부가 기본이며 본문 붙여넣기도 가능합니다. | 제목과 설명만으로 본문 구조와 예외를 알 수 없다. 여러 문서를 합치는 업무에는 두 건 이상이 필요하며 연결 도구의 형식 지원도 확인해야 한다. |
| 결과 양식 | 정해진 양식이 있나요? 있으면 양식 파일이나 필수 항목 목록을 주세요. | 결과가 맞는 형식인지 확인한다. |
| 자료 이용 조건 | 이 자료를 어디에서 읽고 처리할 수 있나요? 외부 AI 서비스로 보낼 수 있나요, 아니면 내부에서만 다뤄야 하나요? | 사용 가능한 방법과 권한을 구분한다. |
| 성공 조건 | 결과를 보고 무엇이 맞아야 성공이라고 판단하나요? | 빠짐·추정·형식 오류를 검토한다. |

실제 문서를 제공할 수 없으면 공개·가상 자료로 흐름을 설명할 수는 있다. 그 결과를 회사 문서에 대한 검증으로 표시하지 않는다. 민감한 원문을 제공하기 어렵다면 가린 대표 문서로 먼저 평가하고, 실제 운영 전에는 회사가 허용한 입력 경로와 처리 조건을 다시 확인한다. 비밀번호와 비밀키는 이 요청서에 적지 않는다.

세 문서 작업에서는 아래 자료를 추가로 요청한다.

| 업무 | 추가로 받을 내용 |
|---|---|
| 여러 문서의 요약 보고서 | 합칠 문서 두 건 이상, 보고서를 읽을 사람, 요약 범위·길이, 문서별 출처 표시 필요 여부 |
| 회의록 정리 | 원래 회의록 본문, 결정 사항과 할 일을 담을 결과 항목, 담당자·기한이 없는 경우의 표시 방식 |
| 정해진 양식의 문서 초안 | 양식 본문이나 필수 항목 목록, 항목을 채울 자료, 정보가 없을 때 빈칸·확인 필요 중 원하는 표시 방식 |

## 3. 해법 선택·반복 적용 때 확인할 내용

| 항목 | 담당자에게 묻는 말 | 없을 때 처리 |
|---|---|---|
| 반복 정도 | 한 번만 할 일인가요, 매주·매달 반복하나요? 한 번에 문서가 몇 개인가요? | 자동화 효과는 미확인으로 둔다. |
| 사용 환경 | 이미 쓰는 문서 도구나 저장 위치는 무엇인가요? 기존 상용 도구에 계정을 연결하거나 새 도구를 사용할 수 있나요? | 환경·도구 연결 적합성을 미확인으로 둔다. |
| 비용·시간 한도 | 월 사용료나 초기 준비에 어느 정도를 허용하나요? 언제까지 필요한가요? | 저비용·기한 적합성을 단정하지 않는다. |
| 담당자 검토 | 생성 결과를 누가 확인하고 최종 사용을 결정하나요? | 자동 전송·확정을 기본값으로 두지 않는다. |

## U-Solve가 정리해 돌려줄 작업 명세 형식

1. **해결할 업무와 현재 절차:** 담당자의 설명을 짧게 재진술한다.
2. **입력과 원하는 결과:** 문서 종류·개수·출력 항목·양식을 기록한다.
3. **확인된 조건과 미확인 사항:** 이용 권한, 외부 전송, 환경, 비용, 기한을 분리한다.
4. **필요한 기능:** 예를 들어 본문 읽기, 항목 추출, 근거 표시, 양식 채우기 중 해당하는 것만 적는다.
5. **다음 단계:** 자료 요청, 해법 비교, 실제 문서 처리 중 지금 가능한 단계와 막힌 이유를 적는다.

담당자가 이 명세를 확인한 뒤 공개 자료와 자체 저장소의 기존 도구·워크플로 후보를 비교한다. U-Solve는 해당 도구를 연결해 실제 입력·결과를 확인하도록 돕는다. 공개 레퍼런스나 특정 도구 이름은 첫 문의의 필수 입력이 아니라 후보의 기능·이용 조건을 확인하는 근거다. 연결·실행 방식과 각 문서 형식의 실제 지원 여부는 아직 정해지거나 검증되지 않았다.
