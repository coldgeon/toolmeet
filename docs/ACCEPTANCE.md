# 툴밋 완료 기준

## 2026-10-13 이슈 #4의 화면 판정

#4의 완료 기준은 두 탭과 상태 보존, 중앙 질문 입력과 흰 집중 전환, 동일 카탈로그 ID의 저장 이미지 배경/기본 목록, 모션 정지·움직임 감소·미디어 실패 대체, 명시적 새 질문 초기화, 뉴스 및 `/toolmeet/` 연결이다. 기존 mock 추천·확인 후 링크와 #1의 이전 응답 무효화 판정을 보존한다.

해당 구현의 DOM 회귀·기존 전체 테스트·빌드와 브라우저 데스크톱/320·360·390px 확인을 수행했다. 합성 저장 SVG를 연결한 것으로 판정하며 실제 도구의 화면·조사·실행·기업 적합성은 미검증이다. OS 움직임 감소 설정·실제 휴대폰·스크린리더·새 PR CI·배포도 별도다. 조건별 대화/실제 단계(#5)와 상세 프리뷰/질문 연결(#6)은 이번 판정에 포함하지 않는다. 세부 실행 증거는 HANDOFF.md를 따른다.

기준: 2026-10-12, Asia/Seoul. [기획](PLAN.md)의 **질문 게시판 `/` → 업무·환경에 따른 관련 AI 소식·후보와 추천 근거 → 방법 미리보기 → 방향 확인 → 원본 링크/첫 사용 확인**과 **별도 AI 뉴스 카테고리 `/news`**가 이번 시연 범위다. 기본 `/`와 `/news`는 mock 데이터의 로컬 시연이며 실제 자동 수집·공급자 실행·기업 적합성을 증명하지 않는다. 이전 5건 탐색은 `/explore`, 세 사례 Markdown 본문→결과물 [실행 기록](demo/RESULTS.md)은 `/demo`의 별도 시험이다. 기존 세 사례는 사람의 전체 원문 대조·웹 화면 조작 검토가 남아 **마감 시연 전체 PASS, 파일 형식 지원, 실기업 적용을 선언하지 않는다**.

## 세 사례와 파일 형식

[내부 입력 세트](demo/README.md)와 [사람 검토용 예상 결과](demo/EXPECTED.md)가 각 사례의 구체적인 원문 사실·행·양식 칸을 정한다. 세 사례 모두 **원본을 보존한 변경 복사본으로 다시 실행**하고 결과가 변경을 따라가야 한다. 내부 자료는 실제 고객 문서나 공급자 실행 기록이 아니다.

| ID | 합격 증거 | 실패 사례 |
|---|---|---|

## 2026-10-12 로컬 시연 부분 판정

- AC-01·03: 기존 `/demo`는 첫 문의 세 항목과 조건을 받아 고정 세 사례의 2D 과정도·빈 구조에 반영한다. `/explore`는 자유 문장으로 시작해 저장된 맥락을 검색한다. 기본 `/`는 질문 게시판에서 mock AI 소식·추천으로 이어지고 `/news`는 별도 뉴스 카테고리다. 어느 화면도 후보의 회사 적합성까지 완료한 것은 아니다.
- AC-04: 설계 승인 뒤 본문 입력을 표시하고, 조건과 연결된 일회용 미리보기 토큰·실행 전체 및 문서별 전송 허용·정책 불가 차단을 서버에서 확인한다. 정책 `모름`에서는 변형되지 않은 내부 시험 문서만 처리하며, 임의 입력은 공개·합성 시험 자료라는 문서별 확인을 요구한다. 공급자·모델·요금이 확인되지 않아 기업 원본은 시연 범위 밖이다. 이 로컬 체크박스는 실제 회사 정책·자료 성격·사용자 인증을 증명하지 않는다. 별도 계정 연결·유료 업무 도구 실행은 없다.
- AC-05·08~10: [RUNS.json](demo/RUNS.json)의 여섯 CLI 실행은 원본·변경본의 본문 해시·실행 시각·결과·원문과 일치하는 인용을 포함하고 상단에 공통 CLI 버전을 기록한다. 이전 회의록·양식 기록에는 실행별 `runtime`·입력 경로 필드가 없다. `review_findings: []`는 문자열·인용 자동 검사다. 사람이 모든 주장과 원문을 대조한 판정은 아직 없다.
- AC-02·06·07·11·12: 후보의 회사 적합성·실제 비용·기한, 운영 대상 쓰기, PDF·Docs/Word·Excel·시트 파일 조합, 반복 운영은 미구현·미검증이다. 공개 n8n 후보의 정적 확인은 실제 설치·연결과 다르다.
