## 세 사례와 파일 형식

[내부 입력 세트](demo/README.md)와 [사람 검토용 예상 결과](demo/EXPECTED.md)가 각 사례의 구체적인 원문 사실·행·양식 칸을 정한다. 세 사례 모두 **원본을 보존한 변경 복사본으로 다시 실행**하고 결과가 변경을 따라가야 한다. 내부 자료는 실제 고객 문서나 공급자 실행 기록이 아니다.

|---|---|---|

## 2026-10-12 로컬 시연 부분 판정

- AC-01·03: 기존 `/demo`는 첫 문의 세 항목과 조건을 받아 고정 세 사례의 2D 과정도·빈 구조에 반영한다. 새 `/`는 자유 문장으로 시작해 저장된 맥락을 검색한다. 두 화면 모두 후보의 회사 적합성까지 완료한 것은 아니다.
- AC-04: 설계 승인 뒤 본문 입력을 표시하고, 조건과 연결된 일회용 미리보기 토큰·실행 전체 및 문서별 전송 허용·정책 불가 차단을 서버에서 확인한다. 정책 `모름`에서는 변형되지 않은 내부 시험 문서만 처리하며, 임의 입력은 공개·합성 시험 자료라는 문서별 확인을 요구한다. 공급자·모델·요금이 확인되지 않아 기업 원본은 시연 범위 밖이다. 이 로컬 체크박스는 실제 회사 정책·자료 성격·사용자 인증을 증명하지 않는다. 별도 계정 연결·유료 업무 도구 실행은 없다.
- AC-05·08~10: [RUNS.json](demo/RUNS.json)의 여섯 CLI 실행은 원본·변경본의 본문 해시·실행 시각·결과·원문과 일치하는 인용을 포함하고 상단에 공통 CLI 버전을 기록한다. 이전 회의록·양식 기록에는 실행별 `runtime`·입력 경로 필드가 없다. `review_findings: []`는 문자열·인용 자동 검사다. 사람이 모든 주장과 원문을 대조한 판정은 아직 없다.
- AC-02·06·07·11·12: 후보의 회사 적합성·실제 비용·기한, 운영 대상 쓰기, PDF·Docs/Word·Excel·시트 파일 조합, 반복 운영은 미구현·미검증이다. 공개 n8n 후보의 정적 확인은 실제 설치·연결과 다르다.
