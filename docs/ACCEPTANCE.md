# U-Solve 완료 기준

기준: 2026-10-11, Asia/Seoul. [기획](PLAN.md)의 **중심 사용자 흐름과 세 문서 사례의 사전 판정 기준 작성**은 완료했다. 제품 코드·연결 도구·실제 입력→출력 기록은 없으므로 **시연, 파일 형식 지원, 실기업 적용은 통과하지 않았다**. 공개 설명이나 내부 합성 자료를 실제 실행·고객 검증 증거로 사용하지 않는다.

| 판정 관문 | 통과에 필요한 증거 | 현재 상태 |
|---|---|---|
| 기획 | 확정·가설·미정, 사용자 흐름, 세 사례의 입력·결과·실패 반례가 PLAN과 이 문서에서 일치 | 세 사례의 사전 기준 작성 완료 |
| 2026-10-12 22:00 세 사례 시연 | **세 사례 모두** 실제 본문 입력·처리 기록·결과물·원문 대조·입력 변경 재실행 기록 | 미실행 |
| 필수 문서 카테고리 | 선택한 PDF·Docs/Word·Excel·시트 대표 **입력→출력 조합별** 실제 파일·실행·결과 증거 | 추가 조합·도구·실행 미정 |
| 기업 적용·반복 AX | 해당 기업의 이용 허용, 실제 문서 결과·사람 검토, 새 문서 재실행·중복 방지·복구 기록 | 실기업 자료·실행 없음 |

## 공통 판정

| ID | 통과 조건과 확인 방법 | 실패 사례 |
|---|---|---|
| AC-01 접수 | 기술명·공개 레퍼런스·실제 문서 없이도 [첫 문의 3항목](PLAN.md#실무자가-요청하는-형식)으로 명세 초안을 만든다. 이후 후보를 바꾸는 원본·출력·회사 정책·기존 서비스·필요 시 비용/기한만 확인하고 `모름`을 받는다. | 첫 문의에서 계정·실제 문서를 필수로 요구하거나 모르는 조건을 허용으로 추정한다. |
| AC-02 후보 적합성 | 후보의 입력·출력·순서·권한·비용·변경 단계를 원문과 대조하고 `그대로/일부 변경/미확인·없음`의 이유를 표시한다. 필수조건 충돌 시 제외, 판정 필수조건이 없으면 개인화 추천·순위·시작 절차를 보류한다. | 후보 수를 채우려고 부적합한 해법을 추천하거나, 코드·가이드 존재만으로 설치·실행·저비용을 확정한다. |
| AC-03 시뮬레이션 | 실제 문서 없이도 현재→제안 절차와 **빈** 예상 출력, 가정·미확인을 보여주고 수정에 따라 갱신한다. 회의록은 2D 과정도·빈 표를 사용한다. 다른 2D·3D 보기는 이해에 도움이 되고 근거가 있을 때만 제공한다. | 가상 내용을 실제 문서 결과·정확한 도면·실행 성공으로 표시하거나, 필수조건 미응답이라는 이유로 빈 미리보기도 막는다. |
| AC-04 실행 허용 | 방향 승인 후 실제 문서·양식·성공 기준을 받고, **해당 문서·도구별** 전송·계정 연결·유료 호출 허용을 각각 확인한다. 파일 첨부와 본문 붙여넣기 입력을 구분해 기록한다. | 설계 승인이나 사전 정책상 `가능`만으로 외부 동작을 실행하거나 허용되지 않은 유료 호출을 한다. |
| AC-05 실행 증거 | 실제 본문을 읽은 도구의 입력·출력·시각·버전·결과물·원문 근거를 기록하고 사람이 대조한다. 문서상 지원·코드 정적 확인·작성자 주장과 U-Solve 실제 실행 상태를 구분한다. | 제목·미리 작성한 정답만 사용하거나 실행 기록 없이 `처리 완료`·`AX 완료`로 표시한다. |
| AC-06 첫 시험 쓰기 | 운영 시트·공유 문서에 쓰기 전 시험 대상·검토자·복구 방법을 정한다. 공개 n8n 후보가 바로 Sheets에 추가하는 경우 시험용 시트·복제본 또는 승인 대기 단계를 실제로 확인한다. | 검토 전 운영 대상에 바로 쓰거나 필요한 변경·시험 없이 후보를 `그대로 사용 가능`으로 판정한다. |
| AC-07 비용·기한 | 후보 선택에 영향을 주는 첫 시험의 요금·설정 시간·마감 한도 또는 `모름`을 확인한다. 실제 비용·준비 시간이 미확인이면 `무료`·`저비용`·기한 내 가능을 확정하지 않는다. | 소개 문구의 `Use for free`만으로 무료 운영이나 예산 충족을 주장한다. |

## 세 사례와 파일 형식

[내부 입력 세트](demo/README.md)와 [사람 검토용 예상 결과](demo/EXPECTED.md)가 각 사례의 구체적인 원문 사실·행·양식 칸을 정한다. 세 사례 모두 **원본을 보존한 변경 복사본으로 다시 실행**하고 결과가 변경을 따라가야 한다. 내부 자료는 실제 고객 문서나 공급자 실행 기록이 아니다.

| ID | 합격 증거 | 실패 사례 |
|---|---|---|
| AC-08 여러 문서 요약 | 서로 다른 본문 3개를 읽어 공통점·차이·조건·출처·미확인을 구분한 보고서를 만든다. 한 문서의 출력 형식을 바꾼 복사본으로 재실행해 보고서가 바뀌는지 확인한다. | 한 문서 누락, 단순 나열, 후보 간 기능 혼합, 근거 없는 비용·복수 문서 지원·실행 성공 단정. |
| AC-09 회의록 후속 조치 | 본문에서 결정과 할 일, 담당자·기한·원문 위치를 구분한 표를 만든다. 없는 값은 사용자 지정 표기(없으면 `미확인`)로 남긴다. 기한을 바꾼 복사본으로 재실행한다. | 결정/할 일 혼합, 담당자·기한 추정, 기본 기한 임의 부여, 근거 없는 행, 가상 회의를 실제 회사 회의로 표시. |
| AC-10 양식 초안 | 양식 본문과 근거 문서를 각각 읽고 모든 항목을 채우거나 근거 없는 칸을 **사용자가 지정한 방식**으로 남긴다. 내부 시연의 기본 표기는 `미확인`이다. 양식 항목을 바꾼 복사본으로 재실행한다. | 항목 누락, 없는 비용·계정·실행 상태·복수 문서 지원 확정, 양식 변경을 무시한 고정 답변. |
| AC-11 파일 카테고리 | 사용자가 추가 대표 조합을 정하면 PDF, Docs·Word, Excel·시트의 **각 선택 조합**에서 실제 파일 본문·출력·형식별 오류를 확인한다. 입력값 변경, 권한 부족, 읽을 수 없는 파일도 기록한다. | Markdown 세 사례나 공급자 설명만으로 해당 파일 형식의 지원·전 조합 통과를 주장한다. |
| AC-12 반복 적용 | 반복 기능을 제공한다고 주장할 때 새 문서와 동일 문서 재실행, 중복 행 방지, 사람 검토, 오류 복구 기록을 확인한다. | 한 번의 시연을 반복 AX 완료로 표시하거나 재실행 중복을 방치한다. |

세 사례 중 **하나라도** 실제 본문→결과물·변경 재실행 증거가 없으면 마감 시연 전체를 통과로 표시하지 않는다. 그 시연을 통과해도 실제 PDF·Docs/Word·Excel·시트 연동, 기업 적합성, 반복 자동화는 별도 미검증이다. 추가 파일 조합·공급자·비용·권한·실행 위치는 결정 후 기준을 보강한다. 한국어 Threads 자동 수집과 AI 소식 통합은 이번 완료 기준 밖이며, 후속 채택 시 **실제 자동 수집 기록**으로 따로 판정한다.
