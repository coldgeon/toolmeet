시뮬레이션은 설계 방향 확인의 완료 기준이며 실제 문서 처리·AX 완료 기준을 대체하지 않는다. 세 사례 중 하나라도 연결한 도구가 생성 문서의 실제 본문을 읽지 않았거나 결과물을 생성하지 못했다면 10월 12일의 세 사례 실제 결과 시연 목표는 달성으로 판정하지 않는다. 생성한 Markdown 시험 문서로 세 사례를 통과하더라도 PDF·Docs/Word·Excel/시트 카테고리의 동작이나 사용자 원본 문서 처리, 실제 업무 환경의 AX가 검증됐다고 주장하지 않는다. 각 카테고리는 대표 입력·작업·도구·실행 기록을 따로 확인한다. 기업 요청서의 정보로 작업 명세를 만들고 미확인을 표시하는 흐름이 우선이다. 공개 후보의 실물과 이용 조건, 사용자 문서 입력 경로, 추천 워크플로의 출력 형식, 제작자 흐름 포함 여부, 저비용 기준, 실제 실행 검증 수준이 결정되면 나머지 후보를 승인·수정·삭제한다. 현재 문서의 제품 검증 후보는 구현 완료를 뜻하지 않는다.

자동 수집과 환경 적합성의 제품 통과 기준은 후속 답변으로 정한다. 이번 문서 작성은 자동 수집 성공이나 환경 실행 성공의 증거가 아니다.

- 각 필수 기능에는 입력, 기대 결과, 검증 명령 또는 수동 확인 절차를 붙인다.
- 실제 자동 수집과 재생·샘플 데이터는 별도로 판정한다.
- 출처 없는 결론, 조건 불일치, 미확인 정보를 포함한 실패 사례를 평가한다.
- 환경 지원 문서와 실제 실행 성공을 구분한다.
- 화면이 보이는 것과 데이터가 실제로 흐르는 것을 구분한다.
- 예산이나 계정 접근이 필요한 항목은 준비 상태와 한도를 기록한다.
- 기획 문서와 실행용 Seed의 요구사항을 일치시킨다.
