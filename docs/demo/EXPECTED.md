# 내부 시연 사전 판정표

이 문서는 사람이 결과를 검사할 때 쓸 **시험 오라클**이다. 제품에 넣을 정답 데이터나 실제 실행 결과가 아니다. 원본 입력은 [시연 입력 세트](README.md)에 있고, 공개 소개 페이지의 설명과 가상 회의 내용을 구분한다. 세 사례 모두 도구가 입력 **본문**을 읽은 기록과 실제 결과물이 있어야 통과한다.

## 1. 여러 문서 요약 보고서

입력: `workflow_summary.md`, `workflow_meeting.md`, `workflow_template.md` 세 파일을 함께 사용한다.

| 원본 | 결과에 반영할 핵심 사실 | 반드시 남길 조건·미확인 |
|---|---|---|
| 요약 후보 A | URL·텍스트·PDF 입력을 설명하고 결과 형식은 Markdown이다. 이미지 PDF 대체 경로는 OCR.Space다. | 여러 문서를 하나의 보고서로 합치는 기능, 실제 비용·실행은 미확인이다. |
| 회의록 후보 B | 웹훅 회의 메모를 받아 Gemini로 요약·결정·할 일을 추출하고 Google Tasks·Gmail·Docs로 이어진다. | Google 권한이 필요하며 한국어 정확도와 실제 실행은 미확인이다. |
| 양식 후보 C | Google Docs 양식과 Apps Script를 사용해 값을 채우고 PDF 링크를 제공한다고 설명한다. | 호스팅 조건의 소개 문구가 서로 엇갈리고 실제 실행·무료 범위는 미확인이다. |

- 기대 결과: 세 문서의 목적·입력·출력·준비 조건을 구분하고 각 사실에 해당 원본 파일과 공개 URL을 연결한다. **공통점**은 공개 설명에 AI를 이용한 문서 처리 흐름과 별도 계정·설정 조건이 있다는 수준에서만 적는다. **차이**는 A가 Markdown 요약, B가 Tasks·Gmail·Docs 후속 조치, C가 Docs 양식에서 PDF 링크 생성이라는 목적·출력 차이를 적는다. 세 후보가 모두 실제로 동작하거나 무료라는 결론은 낼 수 없다.
- 실패: 한 문서가 빠지거나, 세 문서의 사실을 단순 나열하고 공통점·차이를 비교하지 않거나, A의 `여러 문서 합치기`를 확인된 기능으로 적거나, B·C의 계정·실행 조건을 지우거나, 서로 다른 후보의 기능을 한 후보에 섞는다.
- 변경 반례: **원본을 보존한 복사본**에서 A의 출력 형식을 시험용으로 `HTML`이라고 바꾸고 다시 처리한다. 결과가 그 변경을 반영해야 하며, 복사본의 변경 사실을 공개 출처가 보증한다고 말하면 실패다.

## 2. 회의록 결정·할 일 표

입력: `mock_meeting.md`. 회의·사람·결정은 모두 합성이다.

| 종류 | 원문에서 확인할 내용 | 결과 판정 |
|---|---|---|
| 결정 | 세 후보를 검토 목록에 남기되 실행 전 `그대로 사용 가능`으로 표시하지 않는다. | 결정으로 분류하고 가상 회의록의 결정 문장을 근거로 연결한다. |
| 할 일 1 | 평가 담당 A가 2026-10-12까지 요약 후보의 복수 문서 보고서 가능성을 확인한다. | 담당자 A와 기한 2026-10-12를 원문대로 적는다. |
| 할 일 2 | 평가 담당 B가 회의록 후보의 필수 권한을 정리한다. | 담당자 B를 적고 기한은 추정하지 않아 `미확인`으로 남긴다. |
| 할 일 3 | 양식 후보의 호스팅 조건을 추가 확인한다. | 담당자·기한을 추정하지 않아 둘 다 `미확인`으로 남긴다. |

- 각 결과 행은 회의록의 대응 문장·위치를 가리켜야 한다. `미확인`은 이 시험 요청의 표시 문구이며 다른 실제 요청에는 사용자가 지정한 표기를 따른다.
- 실패: 검토 목록 유지라는 결정을 할 일로 바꾸거나, 없는 담당자·기한을 채우거나, 실제 회사 회의라고 적거나, 근거 없는 행을 추가한다.
- 변경 반례: 복사본에서 할 일 1의 기한을 `2026-10-13`으로 바꾸고 다시 처리한다. 결과도 2026-10-13으로 바뀌어야 한다. 원본 파일은 수정하지 않는다.

## 3. 정해진 양식의 문서 초안

입력: `evaluation_template.md`와 `workflow_summary.md`를 별도 파일로 사용한다. 아래는 요약 후보 A를 평가하는 경우의 사전 판정이다.

| 양식 항목 | 기대 내용 또는 상태 |
|---|---|
| 1. 해결하려는 작업 | **사용자의 업무:** 여러 문서를 한 보고서로 요약하고 문서별 근거를 남기기. 후보 A가 이를 지원하는지는 미확인이다. |
| 2. 후보 이름·설명 | 요약 후보 A와 URL·텍스트·PDF 입력 요약이라는 한 줄 설명. |
| 3. 입력·출력 | URL·텍스트·PDF → Markdown 요약이라는 공개 설명의 범위. |
| 4. 계정·권한·환경 | n8n 인스턴스, OpenAI 또는 OpenRouter 키, 이미지 PDF 대체 경로의 OCR.Space 키가 언급됨. 실제 계정 준비 여부는 미확인이다. |
| 5. 비용·무료 범위 | 실제 총비용은 `미확인`. `Use for free`를 무료 운영 확정으로 쓰지 않는다. |
| 6. 적합성 판정 | 복수 문서 통합 보고서 요구에는 `적합성 미확인`; 입력 유형 지원만으로 `그대로 사용`이라고 하지 않는다. |
| 7. 변경할 단계 | 변경이 필요한지와 정확한 노드는 실제 워크플로 대조 전이므로 `미확인`. |
| 8. 근거 | 원본 문서에 적힌 [공개 소개 URL](https://n8n.io/workflows/8210-summarize-content-from-urls-text-and-pdfs-using-openai/)과 확인 날짜 2026-10-11. |
| 9. 실제 실행 | U-Solve 환경에서 실제 실행 확인 전이므로 `미확인` 또는 `실행 미검증`. |
| 10. 남은 질문 | 복수 문서 통합, 비용, 계정·권한, 설치 성공 여부 등 실제 판단을 바꾸는 질문. |

- 기대 결과: 양식의 10개 항목을 빠짐없이 채우되 근거가 없는 곳을 명시하고, 결과가 `양식 초안`임을 표시한다.
- 실패: 키·로그인이 이미 준비됐다고 꾸미거나, 비용·복수 문서 통합·실행 성공을 확정하거나, 양식 항목을 생략한다.
- 변경 반례: 복사본 양식의 3번 항목을 `입력·출력·저장 위치`로 바꾼 뒤 다시 처리한다. 결과에 새 항목이 나타나고 근거 없는 저장 위치는 `미확인`이어야 한다. 원본 양식은 수정하지 않는다.

## 공통 기록 형식

각 시험마다 입력 파일·변경 복사본, 후보 도구·버전, 실제 도구 입력/출력, 실행 시각, 시험 대상 시트·복제본, 검토자와 운영 대상 반영 여부, 실패·오류, 사람이 검토한 결과와 원문 근거를 남긴다. 이 기록이 없으면 `미실행`이다. Markdown 시험의 성공은 실제 PDF·Docs/Word·Excel/시트 파일 지원이나 기업 환경 적합성의 증거가 아니다.
