# 로컬 Markdown 시연 기록

2026-10-12(Asia/Seoul), Codex CLI `0.162.1`의 기본 모델 설정으로 [내부 시험 입력](README.md)을 처리했다. [전체 실행 기록](RUNS.json)에는 각 입력의 SHA-256, 실행 시각, 결과물과 원문 일치 여부를 확인한 인용이 있다. 이 기록은 **공개 설명 요약·가상 회의**의 실제 본문 처리 결과이며, 기업 문서나 공개 n8n 워크플로를 설치·실행한 결과가 아니다.

| 사례 | 원본→결과 | 원본을 보존한 변경 복사본 | 자동 사전 점검 |
|---|---|---|---|
| 여러 문서 요약 | A·B·C의 공통점·차이·준비 조건·미확인과 세 공개 URL을 비교한 보고서 | A의 출력 설명을 Markdown→HTML로 바꾸자 보고서의 해당 항목이 바뀜 | 인용 29/29·16/16 원문 일치, 사전 점검 통과 |
| 회의록 후속 조치 | 가상 결정·할 일, 담당자·기한·원문 근거 표 | A의 기한을 10월 12일→13일로 바꾸자 해당 행이 바뀜 | 인용 6/6·6/6 원문 일치, 사전 점검 통과 |
| 양식 초안 | 사용자의 복수 문서 보고서 업무에 대한 평가 양식 10항목 초안 | 3번 항목에 `저장 위치`를 추가하자 초안도 이를 추가하고 값을 `미확인`으로 둠 | 인용 11/11·14/14 원문 일치, 사전 점검 통과 |

양식 사례의 첫 시험에서는 요청 문구가 사용자 업무를 `양식 작성`으로 잘못 적어 1번 항목이 [사전 판정표](EXPECTED.md)와 달랐다. 시험 요청 문구와 자동 점검을 고친 뒤 **양식 사례 두 판본을 다시 실행**했고 위 표에는 수정 후 실행만 담았다. `RUNS.json`의 양식 실행 시각은 수정 후 기록이다.

요약 사례도 첫 결과에서 공개 URL이 빠진 것을 대조 중 발견했다. 결과 지시와 자동 점검에 세 URL 확인을 추가해 **원본·변경본을 다시 실행**했고 위 표에는 수정 후 실행만 담았다. 변경본의 HTML 표기는 시험용 복사본의 내용이며 공개 출처를 다시 조회해 확인한 사실이 아니다.

이 표의 `통과`는 스크립트의 기본 사전 점검이다. 결과의 모든 주장과 원문 대응, 회사별 적합성은 **사람 검토 대기**다. PDF·Docs/Word·Excel·시트 파일 연동, 실제 사용자 문서, n8n 후보 설치·비용·권한, 반복 자동화, 3D 보기는 이 시험으로 판정하지 않는다.
