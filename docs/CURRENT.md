# U-Solve 현재 상태

기준: 2026-10-12, Asia/Seoul. 최신 결정은 [PLAN.md](PLAN.md), 시연 판정은 [ACCEPTANCE.md](ACCEPTANCE.md)를 따른다.

## 현재 제품 방향

- 사용자의 최신 요청은 **전체적으로 게시판 형식**, 메인 `/`에는 코멘토 참고 화면처럼 **바로 질문하는 큰 입력창**, AI 소식은 `/news`의 **별도 뉴스 카테고리**다. 질문의 업무와 사용 환경에 따라 관련 소식→AI 서비스·공개 프로젝트 후보→추천 이유·적합성/보류 근거→활용 방법 미리보기→방향 확인→원본 링크·첫 사용 확인점이 달라진다. 다른 분야 소식도 `/news`에서 볼 수 있다.
- 기본 `/`와 `/news`는 **로컬 mock 프로토타입**이다. 메인의 예시 질문은 가상 게시글이며 사용자가 쓴 질문은 현재 화면에서만 처리하고 공개 게시·서버 저장하지 않는다. `/explore`는 이전 공개 설명 요약·코드 정적 확인 5건의 키워드 탐색과 참고 2D 과정도, `/demo`는 세 문서 사례의 공개·합성 Markdown 본문 처리 시연이다. 경로별 증거 수준과 완료 판정은 다르다.
- 게시판·뉴스 화면 Seed는 `seed_d5f3732c4c93`, 앞선 소식·추천 Seed는 `seed_a4d15145d51b`, 이전 탐색은 `seed_793e5958492a`, 세 사례 본문 처리는 `seed_4653830ccd93`이다. Seed 실행기·Ralph·유료 수집은 실행하지 않았다. 질문·뉴스 정적 mock 판은 2026-10-12에 Sites로 **공개 배포**했다.

## 구현과 증거 경계

- `data/brief_mock.json`의 **가상 질문·소식·후보 설명**을 `brief_engine.py`의 `MockBriefRepository`가 읽는다. `/api/board`는 예시 질문, `/api/news`는 분야별 소식을 제공한다. 저장된 단어 규칙으로 업무를 임시 분류하고, 외부 AI 정책·설치·업무 환경·시험 자료·n8n 실행 위치 조건에 따라 관련 소식의 맥락/연결 후보, 추천 이유, 적합성/보류, 첫 사용 확인점을 계산한다. 일치 단어가 없으면 특정 서비스 추천을 보류한다. AI가 자유 문장을 이해하거나 실제 기사를 수집한 결과가 아니다.
- 기본 화면은 `web/index.html`·`brief.css`·`brief.js`, 뉴스 화면은 `web/news.html`·`news.js`다. `/api/brief` 초기 응답에는 원본 URL이 없다. 조건상 검토 가능한 후보의 활용 방법을 본 후 방향을 확인해야 `/api/brief/confirm`이 URL을 제공한다. `모름/불가` 또는 설치·자료 조건의 충돌/미확인은 보류·제외 이유와 확인 행동을 보여준다.
- [공개 정적 mock 화면](https://u-solve-board-demo-20261012.stony-grove-6981.chatgpt.site)은 `site/src/`의 복사본과 브라우저 내 mock API로 `/`·`/news/`를 제공한다. 질문은 서버로 전송되지 않는다. 정적 배포판의 링크 확인은 화면 흐름이며 서버 보안 경계가 아니다. 기존 `/explore`·`/demo`는 로컬 Python 서버에서만 제공한다. 소스는 [seongwwww/u-solve](https://github.com/seongwwww/u-solve) 비공개 저장소 `main`에 푸시했다.
- **mock 판정의 ‘조건상 검토 가능’은 실제 계정 사용 가능·회사 승인·가격/기능 확인이 아니다.** 서비스·프로젝트 링크의 현행성, 요금, 형식 지원, 기업 적합성, 실제 설치·파일 처리·Threads 자동 수집은 검증하지 않았다. 기본 `/`와 `/explore`는 외부 AI·유료 API를 호출하거나 기업 자료를 보내지 않는다. `/demo`의 Codex CLI 본문 처리는 별도이며 기업 원본은 사용하지 않는다.
- 기존 세 사례의 공개·합성 Markdown 원본·변경본 여섯 실행은 [자동 사전 점검](demo/RESULTS.md)을 통과했다. 사람의 전체 원문 대조와 브라우저 화면 검토가 남아 기존 마감 시연 전체 PASS나 실기업 적용을 선언하지 않는다.

## 검증과 다음 작업

- 새 mock 흐름과 이전 탐색의 `python3 -m unittest discover -s tests -v` **8개 시험이 통과**했다. 정적 배포판은 `node site/build.mjs`, `node site/test_static.mjs`에서 게시판·뉴스·업무/환경별 추천·확인 후 링크를 확인했고 자산 HTTP 200과 Sites 배포 성공 상태를 확인했다. Python·JS 구문 검사, JSON 파싱, `git diff --check`도 통과했다. 이 환경에는 브라우저 제어 도구와 로컬 브라우저가 없어 직접 조작·시각 검토는 미완료다.
- Windows GitHub CLI에 로그인된 `seongwwww` 계정을 확인해 개인 비공개 저장소 `seongwwww/u-solve`를 만들고 로컬 커밋 `95e6604`를 `main`에 푸시했다. 공개 배포 URL의 `/`·`/news/`·JS·JSON은 인증 없는 외부 HTTP 200으로 확인했다. `coldgun` 초대 API는 `coldgun is not a user`(404)를 반환했다. `coldgun`은 `Organization` 계정이며 개인 사용자명 확인이 남았다.
- 비공개 저장소의 GitHub Pages를 시도했지만 GitHub가 현재 요금제에서 지원하지 않는다고 422로 거절했다. 시험용 `gh-pages` 브랜치는 삭제했다. 실제 공개 배포는 위 Sites URL이며 저장소 홈페이지에도 연결했다.
- 실제 연동의 다음 단계는 뉴스 공급원·수집/갱신·출처/발행일/중복 검증, 서비스·프로젝트 카탈로그의 현행성·계정·가격·형식 검증, 회사 정책·자료 전송 허용과 대표 자료의 사람 검토다. 한국어 Threads 자동 수집은 샘플이나 수동 URL 입력으로 충족했다고 판단하지 않는다.
- 가상 기업 실무자와 독립 기획 검증자의 피드백은 내부 합성 검토이며 고객 인터뷰나 시장 검증이 아니다. 별도 작업 트리의 미병합 변경은 보존한다.
