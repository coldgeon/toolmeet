# U-Solve 현재 상태

- 기준일: 2026-10-11, Asia/Seoul.
- 이번 프로토타입의 중심은 **박찬건 방향의 실무자 문서 업무 해결**이다. AI 소식 정리와 업무별 도구 추천의 독립·부분 연결·통합은 아직 결정하지 않았다.
- 이번 중심 사용자 흐름과 세 사례의 입력/예상 출력/실패 기준은 [기획 요약](PLAN.md), [상세 기획](PRODUCT.md), [완료 기준](ACCEPTANCE.md)에 정리했다. **세 사례의 기획·사전 판정 기준 작성은 완료**했지만 필수 파일 카테고리의 대표 조합·수용 범위는 미정이며, 제품 구현이나 시연 통과도 아니다.
- 과제 마감은 2026-10-12 22:00(Asia/Seoul) 전으로 사용자가 확인했다. 목표는 여러 문서 요약, 회의록의 결정·할 일 정리, 정해진 양식 초안 **세 사례 모두** 입력 본문을 읽고 각각의 결과물을 보여주는 것이다.
- 현재 제품 코드·도구 연결·입출력 실행 기록은 없다. [내부 Markdown 입력](demo/README.md)과 [사전 판정표](demo/EXPECTED.md)는 준비했으나 실제 문서 처리·파일 형식 지원·실기업 AX 효과는 검증하지 않았다.
- 이번 단계에서 코드 구현, 배포, 유료 수집, Ralph 실행은 시작하지 않는다. 구현을 사용자가 요청하면 확정 범위와 완료 기준으로 Seed를 만든다.

## 확정된 사용자 흐름

1. 실무자가 `해결할 업무 / 현재 처리 순서 / 원하는 결과·필수 항목` 세 항목으로 시작한다.
2. U-Solve는 [요청 형식](INTAKE.md)에 따라 후보를 가르는 원본·출력 형식, 회사 정책상 외부 AI 사용 가능성, 기존 서비스·설치 제약만 후속 확인한다. 비용·기한이 선택을 바꾸면 한도도 묻고 `모름`을 허용한다.
3. 공개 웹·GitHub·오픈소스 등의 확인 가능한 자료와 자체 저장소의 설명·코드·워크플로를 근거로 대조한다. 판정 필수조건이 없으면 특정 도구의 개인화 추천·순위·시작 절차를 보류한다.
4. 실제 실행 전 U-Solve 안에서 현재·제안 과정과 **빈 예상 결과 구조**를 시뮬레이션으로 보여준다. 이해·선택에 도움이 될 때 2D·3D를 사용하지만 시뮬레이션을 실제 도면·문서 결과로 표현하지 않는다.
5. 사용자가 방향을 수정·승인한 뒤 실제 문서 본문·양식·계정 권한과 해당 문서·도구의 전송·연결·유료 호출 허용을 별도로 확인한다. 파일 첨부를 기본으로, 본문 붙여넣기도 허용한다.
6. 허용된 기존 도구·워크플로로 대표 문서를 시험하고 결과·원문 근거를 사람이 검토한다. 운영 시트·공유 문서에 쓰기 전에 시험 대상과 복구 방법을 정한다. 실제 입력·출력 기록이 없으면 처리 완료나 AX 완료로 표시하지 않는다.
7. 반복 업무 적용은 별도 성장 단계이며 새 문서 재실행, 중복 방지, 사람 검토·복구가 증명된 범위만 완료로 표시한다.

## 범위와 근거 수준

- 프로토타입의 주 카테고리는 PDF, Docs·Word, Excel·스프레드시트 문서 자동화다. U-Solve는 기존 상용 도구·공개 워크플로를 연결하는 역할이며 자체 범용 문서 처리 엔진을 필수로 두지 않는다. 각 파일·작업 조합의 실제 지원은 별도 실행으로 검증한다.
- 첫 대표 과제는 회의록에서 결정·할 일을 나눠 담당자·기한·원문 근거가 있는 Excel·시트 표로 만드는 일이다. 이 선택은 검증 순서이며 다른 두 사례를 취소하지 않는다.
- 박찬건 개인 [Notion 원문](https://recondite-salute-14b.notion.site/3e40a17c91ac80dfb5bee3acc7f49890?pvs=143)은 2026-10-11 연결 도구로 읽었다. 개인안의 제작자 등록·자동 수집 등은 이번 세 사례 필수 범위로 확정하지 않았다.
- 첫 회의록 후보로 공개 n8n JSON과 커뮤니티 템플릿의 코드·설정 설명을 확인했다. 계정·권한·입출력 차이가 있고 U-Solve에서 실제 가져오기·실행·비용은 미검증이다. Threads 자동 수집도 문서 조사 단계이며 실제 수집 성공을 확인하지 않았다.
- 사용자 확인에 따르면 기존 제품 코드, 정리된 워크플로, 실기업 근거 문서와 협업자 별도 진행 작업은 없었다. 현재 `docs/demo/`의 문서는 이후 만든 내부 합성·공개 설명 요약 자료다.
- `/root/persona_intake`, 가상 실무자, 독립 기획 검증자의 검토는 내부 합성 QA다. 실제 고객 인터뷰·시장 수요 증거가 아니다.
