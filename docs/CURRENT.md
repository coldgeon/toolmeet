- 최근 사용자는 업무별 AI 도구 추천과의 통합을 고려 중이며 아직 확정이 아니라고 명시했다.

- 최신 진행 순서: 박찬건의 아이디어부터 깊이 검토한 뒤 방향을 결정한다. 김성원 안과의 연결 여부는 그 후에 판단한다.
- 박찬건 안의 첫 검증은 간단한 문서 작업에서 시작한다. 사용자 질문을 바탕으로 필요한 기술을 요약하고 우리 저장소의 정보를 사용해 GitHub·오픈소스·기타 방법 중 비개발자도 쉽게 저비용으로 도입할 길을 소개하거나 직접 해결하는 구상이다.
- ‘우리 저장소’에는 기술·도구의 설명과 실행 가능한 코드·워크플로를 함께 담는 방향을 사용자가 선택했다.
- 작은 작업에 정확히 맞는 해법이 드물다는 문제를 풀기 위해, 그대로 사용 가능한 해법과 일부 모듈을 바꾸면 사용 가능한 해법을 근거와 함께 구분한다. 추천 워크플로는 사용자 여정의 중간 단계다.
- 최신 추천 설계안: 회사별 적합성은 원본·출력 형식, 자료 전송·설치·계정 등 필수 조건을 먼저 대조하고, 통과 후보의 변경 노드·비용·운영 부담을 비교한다. 미확인 조건은 조건부로 남기고, 승인 후 대표 문서의 실제 입출력으로 최종 판단한다. 이 기준은 아직 실제 기업 사례로 검증되지 않았다.
- 최신 협업 요청: 기획 답변마다 구체적인 요구가 있는 가상 기업 실무자 에이전트와 독립 기획 검증자 에이전트에게 초안을 보내 피드백을 받고, 사용자에게 핵심을 전달한다. 첫 합성 페르소나는 Google Docs·일부 PDF 회의록을 기존 Sheets의 근거 추적 가능한 할 일 표로 옮기려는 운영팀장이다. 이 조건은 내부 시험 가정이지 실제 기업 수요 증거가 아니다.
- 최신 진행 우선순위: 실제 기업 담당자가 어떤 업무를 해결하고 싶은지, 현재 어떻게 처리하며 어떤 결과를 원하는지부터 U-Solve의 요청 형식으로 받는다. 공개 레퍼런스는 최초 문의의 필수 자료가 아니라 이후 해법 후보를 확인할 때 쓰는 근거다.
- 사용자가 첫 문의는 업무·현재 방식·원하는 결과 세 항목만 받고 실제 문서와 처리 조건은 그 단계에 요청하는 방식을 재확인했다. 실제 처리 단계의 문서는 파일 첨부를 기본으로, 본문 붙여넣기도 허용한다. 파일별 지원 형식과 링크 연결은 미정이다.
- 최신 사용자 정정: 프로토타입은 문서 자동화를 주 카테고리로 삼고 PDF, Docs·Word, Excel·스프레드시트 업무를 필수 범위로 고려한다. U-Solve는 이미 상용화된 도구·워크플로를 업무에 맞게 찾고 연결하는 역할이다. 자체 범용 문서 처리 엔진 구현은 필수로 두지 않는다. 각 형식의 실제 지원은 연결 도구별로 검증해야 한다.
- 최신 확정: U-Solve가 먼저 가정한 업무 흐름과 예상 결과를 **실제 실행이 아닌 시뮬레이션**으로 보여준다. 사용자가 방향을 수정·승인하면 필요한 실제 문서·계정·권한·비용 조건을 안내하고 기존 도구로 첫 시험 실행·결과 확인을 진행한다. 이후 반복 자동화를 해당 도구에 연결한다. 단순 링크나 시뮬레이션만으로 처리·AX 완료라고 하지 않는다.
- 도구를 U-Solve 안에서 호출해 결과를 돌려줄지, 외부 도구로 안내·설정해 사용자가 실행할지는 미정이다. 어느 쪽이든 실제 입력·출력을 확인해야 처리 완료라고 한다. PDF·Docs·Word·Excel·시트 각각의 대표 작업·공급자·권한·비용도 미정이다.
- 최신 사용자 정정: 시각적으로 보여주는 것이 중요하다. 단순 문서 작업이나 설계 분야에만 한정하지 않고, 복잡한 업무의 과정 또는 예상 결과를 2D·3D로 보여주는 것이 이해·선택에 도움이 되면 U-Solve 안에서 진행한다. 특정 작업에 필요한 표현, 입력 자료·정밀도·연결 도구와 10월 12일 시연 범위는 미정이다. 개념 시뮬레이션을 실제 도면·모델 검증으로 표현하지 않는다.
- 최신 사용자 정정: 제품은 실제 사용자 문서 본문을 읽고 그 내용으로 작업해야 하며, 가능한 범위에서 실제 업무의 AI 전환(AX)과 결과물 확인까지 도와야 한다. 방법만 찾는 경험을 최종 성공으로 취급하지 않는다.

## 현재 자료와 검증 수준

- Windows 원본 폴더에는 기획 Markdown, 신청서 PDF/HWPX, 1분 스피치 PPTX가 있다.
- 원본 폴더에서 제품 코드는 확인되지 않았으며 이전 작업으로 Linux 폴더에 빈 Git 저장소를 초기화했다.
- 사용자는 이미 만든 제품 코드나 정리된 워크플로 자료가 전혀 없다고 확인했다.
- 사용자는 기존 시연용 문서와 근거 문서가 모두 없으며, 찾은 근거를 바탕으로 입력 문서를 생성해야 한다고 확인했다. 박찬건·김성원이 별도로 진행 중인 작업도 없다.
- 2026-10-11 공개 n8n 워크플로 소개 페이지 세 곳의 내용을 짧게 정리한 문서, 가상 회의록, 빈 평가 양식을 `docs/demo/`에 작성했다. 이는 선택적 내부 시험 자료이며 기업 요청 형식이나 제품 처리 결과가 아니다.
- 시연용 문서는 확인 가능한 출처와 생성한 내용을 분리해 표시한다. 생성한 문서 본문을 실제로 읽어 처리하는 시연과 실제 사용자가 가져온 문서에서의 검증은 서로 다른 수준이다.
