# U-Solve 확정 기획 요약

기준: 2026-10-11, Asia/Seoul. 이 문서는 **이번 프로토타입의 중심 사용자 흐름과 세 문서 사례에 대한 기획 결론**이다. 필수 PDF·Docs/Word·Excel/시트 카테고리의 대표 실제 파일 입출력 조합은 아직 결정되지 않아 파일별 제품 수용 범위까지 닫힌 명세는 아니다. 상세 설계는 [PRODUCT.md](PRODUCT.md), 판정 기준은 [ACCEPTANCE.md](ACCEPTANCE.md), 현재 준비 상태는 [CURRENT.md](CURRENT.md)를 따른다.

## 제품 목적과 범위

- 첫 사용자는 기술 이름보다 해결할 문서 업무를 아는 실무자다.
- U-Solve는 업무를 명세화하고, 공개 근거와 자체 저장소의 도구·코드·워크플로를 비교해 `그대로 사용 가능 / 일부 변경 시 가능 / 적합성 미확인·없음`의 이유를 보여준다.
- U-Solve는 실제 도구 실행 전에 과정과 빈 결과 구조를 시뮬레이션하고, 허용된 기존 도구로 대표 문서의 본문을 읽어 결과를 시험·검토하도록 돕는다.
- 실제 처리·변환은 기존 상용 도구나 공개 워크플로를 연결해 수행하는 방향이다. 자체 범용 문서 처리 엔진은 필수 기능으로 정하지 않았다.
- 이번 프로토타입의 중심은 **박찬건 안의 실무자 문서 업무 해결**이다. 김성원 안의 AI 소식 정리와의 통합은 결정하지 않았고 첫 시연의 통과 조건에 넣지 않는다.
- PDF, Docs·Word, Excel·스프레드시트 업무는 제품의 필수 문서 카테고리다. 모든 형식과 작업 조합이 지원된다는 뜻은 아니며 카테고리별 실제 입력·출력을 각각 증명해야 한다.

## 한 업무의 사용자 흐름

1. 실무자는 `해결할 업무 / 현재 처리 순서 / 원하는 결과·필수 항목` 세 가지만 먼저 적는다.
2. U-Solve는 작업 명세를 돌려주고, 후보 선택을 바꾸는 원본 위치·형식, 출력 형식, 회사 정책상 외부 AI 사용 가능성, 기존 서비스·설치 제약만 짧게 묻는다. 비용·기한이 후보를 바꾸는 경우 그 한도도 묻고 `모름`을 허용한다.
3. U-Solve는 확인된 공개 자료와 회사 조건을 대조한다. 판정 필수조건이 빠지면 개인화 추천·순위·시작 절차를 보류하고, 공개 도구는 `일반 참고 사례·적합성 미판정`으로만 보여준다.
4. U-Solve는 현재→제안 절차와 **내용이 채워지지 않은** 예상 결과를 2D 과정도·표·양식 등 적합한 방식으로 보여준다. 복잡한 업무에서 판단에 도움이 되면 3D 개념 보기도 검토한다. 이 화면은 `시뮬레이션`이라고 표시한다.
5. 실무자가 방향을 수정·승인하면 실제 문서·양식·계정 권한, 해당 문서와 도구의 자료 전송·계정 연결·유료 호출 허용을 별도로 확인한다. 설계 승인이나 사전 정책상 `가능`은 실행 허용이 아니다.
6. 허용된 도구로 첫 시험을 수행하고 입력 본문·실행 기록·결과물·원문 근거를 대조한다. 운영 시트나 공유 문서에 쓰기 전에 사람 검토, 시험 대상, 잘못 썼을 때의 복구 방법을 정한다.
7. 반복 적용을 제공할 때만 새 문서 재실행, 중복 방지, 사람 검토와 복구까지 별도로 검증한다. 실제 입출력이 없으면 처리·AX 완료로 부르지 않는다.

## 첫 세 사례와 마감 판정

2026-10-12 22:00 전 시연 목표는 아래 **세 사례 모두 입력 본문을 새로 읽고 결과물을 만드는 것**이다. [내부 입력 세트](demo/README.md)와 [사전 판정표](demo/EXPECTED.md)는 시험 자료이며 실제 고객 문서가 아니다.

| 사례 | 입력 | 기대 결과 | 대표 실패 |
|---|---|---|---|
| 여러 문서 요약 보고서 | 공개 설명을 요약한 서로 다른 문서 3개 | 문서별 공통점·차이, 출처·조건·미확인을 구분한 보고서 | 한 문서 누락, 출처 없는 기능·비용·실행 성공 단정 |
| 회의록 후속 조치 | 가상 회의록 | 결정과 할 일·담당자·기한·원문 위치를 구분한 표 | 결정/할 일 혼합, 없는 담당자·기한 추정, 근거 없는 행 |
| 정해진 양식 초안 | 빈 평가 양식과 공개 설명 문서 | 양식 항목을 따른 근거 있는 초안, 근거 없는 칸의 `미확인` | 항목 누락, 근거 없는 비용·권한·실행 상태 기재 |

- 각 사례에서 입력 본문의 한 사실을 바꾼 복사본으로 다시 실행해 결과가 달라지는지 확인한다. 미리 작성한 정답을 반환하면 실패다.
- **세 사례의 기획·사전 판정 기준 작성 완료**와 **시연 통과**는 별개다. 지금 준비된 것은 Markdown 입력과 판정 기준이며 제품 코드·도구 연결·입출력 실행 기록은 없다. 필수 파일 카테고리의 대표 조합·수용 기준도 별도 미정이다.
- Markdown 본문 3사례 통과만으로 PDF·Docs/Word·Excel/시트 파일 연동, 실제 기업 문서 처리, 반복 자동화, 고객 AX 효과를 통과 처리하지 않는다.
- 10월 12일에 세 사례 외 추가로 반드시 실제 파일로 증명할 입출력 조합은 아직 사용자 결정이 없다. 별도 판정으로 남기며 임의의 조합을 이미 확정된 마감 조건이라고 주장하지 않는다.

## 에이전트 역할과 기존 도구와의 차이

- AI 에이전트는 업무 설명을 명세로 정리하고, 출처와 조건을 대조하며, 가정이 표시된 설계 미리보기를 만들고, 실제 결과의 누락·추정을 검토하도록 돕는다. 에이전트 수·모델·공급자·구현 구조는 아직 정하지 않았다.
- 기존 공개 템플릿은 특정 입력·계정·출력을 가정한다. U-Solve가 추가할 가치는 **회사 조건과 템플릿 차이의 근거**, 교체할 단계, 실제 첫 결과와 원문 대조를 한 흐름으로 연결하는 데 있다. 이 가치의 사용자 효과는 검증 전 가설이다.
- 첫 참고 후보인 공개 n8n 회의록 워크플로는 시트에 바로 행을 추가하므로, 사람 검토 전 운영 시트 쓰기가 금지된 요청에는 그대로 맞지 않는다. 시험용 시트·복제본 또는 승인 대기 단계를 마련해야 하며 실제 수정·실행은 아직 하지 않았다.
