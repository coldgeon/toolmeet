# U-Solve 문서 업무 해결 기획

기준: 2026-10-12, Asia/Seoul. **확정**은 사용자가 승인한 탐색·판정의 큰 흐름을 뜻한다. 프로토타입 시연 방식과 2D·3D 시각화의 작업별 사양은 별도 세션에서 정한다. **미검증**은 실제 동작·기업 적용을 시험하지 않았다는 뜻이다. 합격 판정은 [완료 기준](ACCEPTANCE.md), 기존 내부 입력과 실행 기록은 [demo](demo/README.md)를 따른다.

## 목적과 범위

- 첫 사용자는 기술 이름보다 해결할 문서 업무를 아는 실무자다. **확정한 중심 흐름은 대화형 자유 서술 → 솔루션 저장소의 요약 텍스트·컨텍스트 검색 → 근거 있는 방법 제시 → 전체 흐름 미리보기 → 사용자 방향 확인 → 원본 저장소 연결 또는 실행 방법 안내**다. 미리보기의 표현 방식과 시연 범위는 후속 명세다. 세 문서 사례는 흐름을 시험할 예시이지 첫 화면에서 고를 필수 탭이 아니다. 코멘토는 공개 정보를 한 줄 설명·기능·사용자 행동·근거 링크로 정리하는 **자료 형식 참고 사례**다.
- 대용량 솔루션 저장소는 제품 목표다. 현재 로컬 탐색 화면은 기존 공개 설명 요약·코드 정적 확인 **5건**만 검색한다. 검색 결과는 설명상 관련도이며 회사 적합성·현재 URL의 현행성·실제 설치 성공을 보증하지 않는다. 출처별 확인 날짜와 증거 수준을 유지하고, 자료가 없으면 없는 것으로 답한다. 전체 웹 자동 수집은 아직 없다.
- 판정은 `그대로 사용 가능 / 일부 단계 변경 시 가능 / 적합성 미확인·없음`을 구분한다. 입력·출력·작업 순서·계정·권한·비용과 교체할 모듈·담당자·준비물을 보여준다. 필수 조건이 충돌하면 제외하고, 알 수 없으면 개인화 추천·순위·시작 절차를 보류한다. 공개 사례도 회사 적합성 미판정으로 표시한다.
- 기존 상용 도구·공개 워크플로를 연결해 실제 결과까지 확인하도록 돕는다. 범용 문서 처리 엔진을 직접 만드는 것은 필수 범위가 아니다. 주 카테고리는 PDF, Docs·Word, Excel·스프레드시트지만 모든 형식과 업무 조합의 지원을 약속하지 않는다.
- `원본 링크·방법을 안내함`과 `대표 문서로 첫 시험을 마침`, `실제 업무에 반복 적용함`은 별도 상태다. 링크 안내만으로 업무 해결·AX 도입 완료라고 표시하지 않는다. 후보가 보류되면 보류 이유와 다시 판단하려면 확인할 조건·담당 주체·필요한 근거를 남긴다. 담당자 이름은 확인 전 추정하지 않는다.
- 이번 중심은 **박찬건 방향의 실무자 문서 업무 해결**이다. 김성원 방향의 AI 소식 정리를 독립·부분 연결·통합할지는 미정이며 세 사례의 통과 조건에 넣지 않는다. 소식 안에서는 한국어 Threads **실제 자동 수집**, 원문 말투·반응 확인, 우연한 도구 발견, 중복 묶기와 저장·갱신이 후속 요구다. 샘플 데이터나 수동 URL 입력으로 자동 수집을 충족했다고 주장하지 않는다. 제작자 등록·포트폴리오·광범위한 수집, PPT·마스킹도 첫 시연 필수 범위가 아니다.

## 실무자가 요청하는 형식

첫 화면은 아래처럼 **자유 문장 하나**로 시작한다. 이전 첫 문의 3항목은 대화에서 확인할 내부 작업 명세의 구성 요소이며 필수 입력 칸 3개가 아니다. 기술 이름·공개 프로젝트·실제 문서·계정 정보는 이 단계에서 요구하지 않는다.

```text
[첫 문의 예시]
회의록에서 결정과 할 일을 뽑아 시트에 정리하고 싶어.

[대화에서 필요할 때 정리할 명세]
해결할 업무 / 현재 처리 순서 / 원하는 결과와 필수 항목

[후보 판단에 필요한 경우만, 시뮬레이션 전]
원본의 저장 위치·형식과 원하는 결과 형식:
회사 정책상 외부 AI 사용 가능성: 가능 / 불가 / 모름
현재 쓰는 서비스·저장 위치:
새 도구 설치·계정 연결 가능성: 가능 / 불가 / 모름
후보를 바꾸는 비용·기한 한도: 값 / 모름 / 해당 없음

[방향 승인 후 실제 시험 전]
대표 문서·양식과 성공 기준:
이번 문서를 선택한 도구·공급자에 전송할 허용: 허용 / 불허 / 모름
이번 시험의 계정 연결 허용: 허용 / 불허 / 해당 없음 / 모름
이번 시험의 유료 호출 허용: 허용 / 불허 / 해당 없음 / 모름
결과 검토자·시험 대상·잘못 반영했을 때의 복구 방법:
```

여러 문서 요약에는 **두 건 이상**의 원본·요약 범위·독자·출처 표시 기준을, 회의록에는 원문·결과 열·담당자/기한이 없을 때의 표기를, 양식 초안에는 양식 본문·근거 자료·빈칸 표기 기준을 승인 후 확인한다. 파일 첨부가 기본이고 본문 붙여넣기도 받는다. 모르는 조건은 `모름`으로 남긴다. U-Solve가 돌려줄 명세에는 업무·현재 절차, 입력·원하는 결과, 확인된 조건·미확인, 필요한 기능, 다음 단계를 분리한다. 비밀키·로그인 정보는 요청서에 적지 않는다.

## 사용자 흐름과 증거 경계

1. 사용자는 채팅처럼 하려는 일을 적는다. 현재 절차·입력·원하는 결과 중 판정에 꼭 필요한 정보가 빠졌을 때만 짧게 되묻는다. 로컬 시작 화면은 저장된 텍스트를 키워드로 검색하며 AI가 업무를 이해했다고 주장하지 않는다.
2. 요약 텍스트·컨텍스트 저장소에서 관련 자료를 찾고, 출처·확인 날짜·문서상 설명/코드 정적 확인/실제 실행을 구분한다. 관련 검색어가 없으면 저장소의 범위 한계와 추가 질문을 말한다. 감지한 외부 AI 금지 조건은 후보를 제외하고, PDF 입력·Excel 출력처럼 확인되지 않은 형식은 연결을 보류한다. 보류 시에는 정책 확인 담당자에게 물을 내용 또는 원본에서 확인할 형식·권한 등 **다음 확인 행동**을 제시한다.
3. 후보의 **원본에 확인된 단계**와 **U-Solve가 추가 제안하는 단계**를 나눠 방법·필요 조건·교체 지점을 보여준다. 비용·설정 시간·기한이 선택을 바꾸면 첫 시험 전 한도를 묻고, 확인 전 `무료`·`저비용`·기한 적합성을 단정하지 않는다.
4. 실제 문서 없이 U-Solve 안에서 전체 과정, **빈 예상 결과 구조**, 가정·미확인을 미리 보여준다. 사용자가 수정하면 바뀐 방향을 다시 보여준다. 어떤 업무에 2D·3D가 필요한지, 표현 대상·상호작용·데이터·정확도·검증 방법은 별도 세션에서 작업별로 정한다. 기존 로컬 화면의 2D 과정도는 임시 시연 방식이며 제품의 확정 시각화 사양이 아니다. 근거 없는 도면·실제 결과를 꾸미지 않는다.
5. 사용자가 방향을 확인할 때 외부 AI 사용 가능 여부를 `가능 / 불가 / 모름`으로 짧게 확인한다. 자유 서술의 금지 표현은 조기 차단에 사용하지만 모든 표현을 이해한다고 가정하지 않는다. `불가` 또는 `모름`이면 외부 AI 후보의 연결 안내·원본 URL 제공을 보류한다. `가능`이면 원본 저장소·가이드 링크와 준비물·확인할 조건을 안내한다. 이 확인은 설치·도구 연결·회사 적합성·실제 문서 전송 승인이 아니다. 형식 지원 미확인 후보의 링크는 근거 확인용이며 연결은 보류한다.
6. 실제 시험을 하기로 한 다음 단계에서 문서·양식·공급자별 전송·계정·유료 허용을 요청한다. **설계 방향 확인이나 사전 정책상 `가능`은 해당 문서의 전송·계정 연결·유료 호출 허용이 아니다.** 허용된 기존 도구로 대표 문서를 처리하고 사람의 원문 대조·시험용 대상·복구를 확인한 뒤에만 `첫 시험 완료`로 표시한다. 현재 로컬 탐색 화면은 이 단계를 실행하지 않는다.
7. 반복 적용은 별도 성장 단계다. 새 문서 재실행, 중복 방지, 사람 검토·복구를 확인한 범위에서만 반복 자동화 완료라고 표시한다.

AI 에이전트는 업무 설명을 명세로 바꾸고, 후보의 출처·조건을 대조하고, 가정이 표시된 설계 미리보기를 만들고, 실제 결과의 누락·추정을 검토하도록 돕는다. 기존 템플릿과의 차이는 **회사 조건과 템플릿의 차이, 바꿀 단계, 첫 결과의 원문 근거**를 한 흐름으로 연결하는 데 있다. 사용자 효과는 아직 가설이며 에이전트 수·모델·공급자·구현 구조는 정하지 않았다.

## 별도 명세로 넘길 시연·시각화 작업

- **프로토타입 시연:** 사용자에게 보여줄 대표 업무, 시연의 시작·끝, 실제 입력과 가정값의 경계, 화면별 결과·오류·검증 기준을 별도 세션에서 정한다. 현재 로컬 화면과 기존 세 사례의 시험 기록은 후속 명세의 참고 자료이지 제품 시연 사양의 승인 근거가 아니다.
- **2D·3D 시각화:** 전체 업무 흐름과 예상 결과 중 무엇을 보여줘야 이해에 도움이 되는지 업무별로 판단한다. 각 표현은 필요한 자료, 표시할 사실과 가정, 사용자 수정·확인 방법, 구현 단위와 완료 기준으로 나눠 명세한다. 3D는 모든 업무의 기본 요구가 아니다.
- **세션 인계:** 별도 세션은 이 문서의 확정 흐름과 [현재 상태](CURRENT.md), [완료 기준](ACCEPTANCE.md)를 시작점으로 삼고, 후속 결정·검증 결과를 다시 문서에 반영한다.

## 2026-10-12 22:00 기존 시연 목표·기록

**세 사례 모두 입력 본문을 새로 읽고 각각 결과물을 만드는 것**이 목표다. 회의록은 첫 대표 검증 순서일 뿐 다른 두 사례를 취소하지 않는다. [내부 Markdown 입력](demo/README.md)은 공개 설명의 요약과 가상 회의로 만든 시험 자료이며 실제 기업 문서가 아니다.

| 사례 | 입력 | 기대 결과 | 대표 실패 |
|---|---|---|---|
| 여러 문서 요약 보고서 | 서로 다른 공개 워크플로 설명 3개 | 문서별 공통점·차이, 출처·조건·미확인을 구분한 보고서 | 한 문서 누락, 출처 없는 기능·비용·실행 성공 단정 |
| 회의록 후속 조치 | 가상 회의록 | 결정과 할 일·담당자·기한·원문 위치를 구분한 표와 승인 전 2D 과정도 | 결정/할 일 혼합, 없는 담당자·기한 추정, 근거 없는 행 |
| 정해진 양식 초안 | 빈 평가 양식과 공개 설명 문서 | 양식 항목을 따른 근거 있는 초안, 근거 없는 칸의 `미확인` | 항목 누락, 근거 없는 비용·권한·실행 상태 기재 |

각 사례에서 **원본을 보존한 복사본의 사실 한 곳을 바꿔 다시 실행**하고 결과가 바뀌어야 한다. 이전 세 사례의 로컬 본문 처리 화면은 `/demo`에 보존했다. 합성·공개 설명 Markdown 여섯 실행의 [자동 사전 점검](demo/RESULTS.md)은 통과했지만 사람의 전체 원문 대조와 화면 조작 검토는 대기다. 새 기본 화면 `/`는 위 탐색→방법→시뮬레이션→확인→링크 흐름이며 실제 문서 본문이나 외부 AI를 처리하지 않는다. PDF·Docs/Word·Excel·시트 **실제 파일 연동**은 별도 판정이다.

## 공개 근거와 첫 후보의 한계

- 회의록→후속 조치 표를 첫 대표 업무로 고른 근거는 [Microsoft의 회의 생산성 조사](https://www.microsoft.com/en-us/worklab/work-trend-index/will-ai-fix-work), [Google Meet의 회의 메모 기능](https://workspace.google.com/solutions/ai/ai-note-taking/), [Zapier의 공개 템플릿](https://zapier.com/templates/details/extract-action-items-from-meeting-notes)처럼 업무와 기존 해법이 확인되기 때문이다. 이는 U-Solve의 연결 성공, 실제 고객 수요 규모나 비용의 증거는 아니다.
- [n8n 회의록 GitHub 저장소](https://github.com/TrentIndeed/n8n-meeting-action-items)의 JSON·예제·설정 절차는 공개돼 있다. 로컬 텍스트→Claude→Sheets 흐름이고 작성자 Windows 절대 경로의 변경, API·시트 설정이 필요하다. `agreement context` 열 안내와 실제 행 매핑이 다르며 Sheets에 바로 행을 추가한다. PDF·Docs/Word 입력, Excel 파일 출력, 사람 검토 단계는 확인되지 않았다. **코드 정적 확인만 했고 U-Solve에서 실행하지 않았다.**
