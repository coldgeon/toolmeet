# U-Solve

실무자가 자신의 문서 업무를 설명하고 설계 미리보기와 본문 처리 결과를 확인하는 U-Solve의 기획·로컬 시연 저장소다. 현재 시연은 내부 Markdown·텍스트 문서와 연결된 Codex CLI로 동작한다. 기존 n8n 후보 설치, 실제 기업 문서, PDF·Docs/Word·Excel·시트 파일 연동은 별도 검증 대상이다.

## 읽는 순서

1. [현재 상태](docs/CURRENT.md)와 [최근 인계](docs/HANDOFF.md)를 먼저 읽는다.
2. [제품 기획과 요청 형식](docs/PLAN.md), [완료 기준](docs/ACCEPTANCE.md)을 확인한다.
3. [내부 시연 입력](docs/demo/README.md)과 [사전 판정표](docs/demo/EXPECTED.md)를 시험 자료로 참고한다.
4. 페르소나 담당 에이전트는 [역할 인계](docs/PERSONA_AGENT.md)를 읽는다.

`docs/reference/`의 과거 기획과 신청 원본, `docs/SETUP.md`의 개인 WSL 설정은 로컬 전용이다. Git 추적에서 제외하며, 과거 기획의 확정 표현보다 최근 사용자 발언과 `docs/CURRENT.md`를 우선한다. 가상 페르소나와 내부 시연 문서는 실제 고객 검증 자료가 아니다. 이전 상세 문서와 판정 ID는 Git 커밋 `d5c6f78`에서 확인할 수 있다.

## 로컬 시연

Python 3.12 이상과 로그인된 Codex CLI가 필요하다. 서버는 `127.0.0.1`에서만 열린다.

```bash
python3 app.py
```

브라우저에서 `http://127.0.0.1:8765`를 열어 세 고정 사례 중 하나를 고르고 설계 미리보기를 확인한다. 다른 업무를 적어도 본문 처리 방식은 선택한 사례에 따른다. 방향을 승인하면 시험 문서 불러오기와 `.md`·`.txt` 파일 추가·본문 붙여넣기가 나타난다. 이번 실행과 각 문서의 공개·합성 시험 자료 여부 및 Codex 전송 허용을 선택해야 본문 처리를 실행한다. Codex CLI는 로그인된 계정의 외부 모델 서비스를 이용할 수 있으며 실제 공급자·모델·요금은 이 앱에서 확인하지 못한다. 따라서 **기업 원본 문서는 이 시연에 넣지 않는다.** 회사 정책이 `모름`이면 변형되지 않은 내부 시험 문서만 실행된다. 미리보기는 15분짜리 일회용 승인 맥락이며 입력 조건을 고치면 다시 만들어야 한다. 로컬 체크박스는 실제 회사의 정책·사람 신원 확인을 대신하지 않는다. 결과의 원문 인용과 경고는 사람이 검토한다. 시험 자료는 공개 설명의 요약·가상 회의이며 실제 고객 문서가 아니다.

세 사례의 원본·변경 복사본을 다시 시험하려면 다음 명령을 쓴다. 이 명령은 **실제 Codex 호출 여섯 번**을 실행하며, 저장되는 자료는 `docs/demo/`의 공개·가상 입력뿐이다.

```bash
python3 scripts/verify_demo.py --save docs/demo/RUNS.json
```

## 작업 범위와 상태

- 2026-10-12 22:00(Asia/Seoul) 전 목표는 세 문서 사례의 실제 본문→결과물 시연이다. 실행 증거와 남은 판정은 [현재 상태](docs/CURRENT.md)에 기록한다.

- 업무별 AI 도구 추천과 AI 소식 정리의 통합 여부는 미정이다.

작업 지침은 [AGENTS.md](AGENTS.md)에 있다. 비밀키와 로그인 정보는 저장소에 넣지 않는다.
