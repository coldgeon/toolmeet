# U-Solve

U-Solve의 **질문 게시판과 AI 뉴스** 로컬 프로토타입이다. 메인 `/`에서 사용자가 업무를 질문하고 사용 환경을 알려주면 관련 소식, AI 서비스·공개 프로젝트 후보, 추천 이유, 현재 조건의 충돌·미확인, 첫 사용 확인점을 답변으로 연결한다. `/news`는 별도의 분야별 뉴스 목록·상세 화면이다. **질문 예시·소식·추천 판정은 시연용 mock**이다. 사용자의 질문은 공개 게시·서버 저장하지 않는다. 실제 뉴스 수집, AI의 자유문장 이해, 제품 실행, 가격·기능 현행성, 기업 적합성은 검증하지 않았다. 이전 5건의 키워드 탐색은 `/explore`, 세 문서 본문 처리 시연은 `/demo`에 보존했다.

## 읽는 순서

1. [현재 상태](docs/CURRENT.md)와 [최근 인계](docs/HANDOFF.md)를 먼저 읽는다.
2. [제품 기획과 요청 형식](docs/PLAN.md), [완료 기준](docs/ACCEPTANCE.md)을 확인한다.
3. [mock 질문·소식·후보 데이터](data/brief_mock.json), [이전 탐색 카탈로그](data/solutions.json), [내부 시연 입력](docs/demo/README.md)을 시험 자료로 참고한다.
4. 페르소나 담당 에이전트는 [역할 인계](docs/PERSONA_AGENT.md)를 읽는다.

`docs/reference/`의 과거 기획과 신청 원본, `docs/SETUP.md`의 개인 WSL 설정은 로컬 전용이다. Git 추적에서 제외하며, 과거 기획의 확정 표현보다 최근 사용자 발언과 `docs/CURRENT.md`를 우선한다. 가상 페르소나와 내부 시연 문서는 실제 고객 검증 자료가 아니다. 이전 상세 문서와 판정 ID는 Git 커밋 `d5c6f78`에서 확인할 수 있다.

## 배포된 mock 시연

[U-Solve 배포판](https://u-solve-board-demo-20261012.stony-grove-6981.chatgpt.site)은 2026-10-12에 **소유자 전용 접근**으로 배포했다. `/` 질문 게시판과 `/news/` 가상 뉴스가 동작한다. 이 배포판은 [정적 사이트 소스](site/)의 브라우저 내 mock API를 사용한다. 질문은 서버로 전송되지 않고, 외부 AI나 유료 API를 호출하지 않는다. 원본 링크의 방향 확인은 브라우저 화면 흐름이며 보안·회사 승인 경계가 아니다. 정적 배포판에는 이전 `/explore`와 Codex CLI를 쓰는 `/demo`를 포함하지 않았다.

배포판을 다시 빌드·검증하려면 `site/src/`에 최신 `web/index.html`, `web/news.html`, `web/brief.css`, `web/brief.js`, `web/news.js`, `data/brief_mock.json`의 복사본을 반영한 뒤 다음을 실행한다.

```bash
cd site
node build.mjs
node test_static.mjs
```

GitHub 저장소 업로드와 기여자 초대는 연결 확인 후 진행한다. 현재 GitHub 원격 저장소는 연결되지 않았다.

## 로컬 시연

기본 mock 시연과 `/explore`에는 Python 3.12 이상만 필요하다. `/demo`의 기존 본문 처리에는 별도로 로그인된 Codex CLI가 필요하다. 서버는 `127.0.0.1`에서만 열린다.

```bash
python3 app.py
```

로컬 검증은 `python3 -m unittest discover -s tests -v`로 실행한다. 이 검증은 외부 AI 호출 없이 질문·뉴스 API, mock 추천 변화와 링크 확인 경계, 이전 탐색 동작을 확인한다.

브라우저에서 `http://127.0.0.1:8765/`를 열고 다음 순서로 시연한다.

1. 메인의 큰 입력창에 `회의록에서 결정과 할 일을 뽑아 시트에 정리하고 싶어`라고 묻거나 시연 질문을 누른다. 질문 아래 답변에서 **관련 가상 소식 → 연결 후보 → 추천 이유·적합성·첫 사용 확인점 → 활용 방법 미리보기**를 본다.
2. `문서 요약` 예시로 질문을 바꿔 다시 제출한다. 업무 분류, 관련 소식과 추천 후보·이유가 바뀐다.
3. `내 사용 환경 설정`을 열고 외부 AI 사용을 `가능`, 새 도구 설치를 `가능`, 시험 자료를 `공개·합성 자료`로 바꾼다. n8n 회의 템플릿은 실행 위치도 `자체 호스팅 사용 가능`으로 바꾸면 mock 판정이 `확인 전 보류`에서 `조건상 검토 가능`으로 바뀐다. 반대로 외부 AI 사용을 `불가`로 바꾸면 외부 AI 후보를 제외하고 로컬 검토 방법을 보여준다.
4. 후보의 방법을 미리 본 뒤 방향을 확인하면 조건상 검토 가능한 후보에 한해 원본 링크가 나온다. 이는 설치·자료 전송·첫 시험 완료가 아니다.
5. 상단 `AI 뉴스` 또는 `http://127.0.0.1:8765/news`로 이동해 분야 필터·검색·요약 상세를 확인한다. 업무 분야 소식의 `이 소식으로 업무 질문하기`에서 다시 메인 질문 결과로 돌아온다. 의료·교육 등 다른 분야도 뉴스 목록에 있다.

`http://127.0.0.1:8765/explore`의 이전 5건 키워드 탐색은 저장된 설명의 단계와 미검증 보완 단계를 구분한다. 그 화면의 2D 과정도는 참고 구현이며 제품 시각화 사양이 아니다. 기본 `/`와 `/explore`는 문서를 외부로 보내거나 공급자 워크플로를 실행하지 않는다.

기본 `/`와 `/news`는 `data/brief_mock.json`을 `brief_engine.py`의 `MockBriefRepository`가 읽는다. 실제 연동 때 이 저장소 어댑터를 검증된 소식 수집·후보 카탈로그 공급원으로 교체하고 원문 URL·발행/확인 시각·중복·기능·권한·요금을 검증해야 한다. 현재 서비스·프로젝트 링크의 현행성도 재확인하지 않았다.

기존 세 고정 사례의 본문 처리 시연은 `http://127.0.0.1:8765/demo`에 남아 있다. 방향 승인 뒤 `.md`·`.txt` 파일·붙여넣기와 문서별 공개·합성 자료 확인·Codex 전송 허용을 받는다. Codex CLI는 로그인된 계정의 외부 모델 서비스를 이용할 수 있으며 실제 공급자·모델·요금은 이 앱에서 확인하지 못한다. **기업 원본 문서는 넣지 않는다.** 결과의 원문 인용과 경고는 사람이 검토한다.

세 사례의 원본·변경 복사본을 다시 시험하려면 다음 명령을 쓴다. 이 명령은 **실제 Codex 호출 여섯 번**을 실행하며, 저장되는 자료는 `docs/demo/`의 공개·가상 입력뿐이다.

```bash
python3 scripts/verify_demo.py --save docs/demo/RUNS.json
```

## 작업 범위와 상태

- 2026-10-12 22:00(Asia/Seoul) 세 문서 사례 시연은 기존 목표다. 자동 사전 점검 증거는 있으나 사람의 원문 대조와 웹 화면 검토가 남아 전체 판정은 대기 중이다. 최신 방향 승인과 별도로 [현재 상태](docs/CURRENT.md)에 기록한다.
- 대용량 저장소와 대화형 AI 응답은 제품 목표다. 현재 5건 검색의 정확도·확장성은 아직 검증하지 않았다.
- PDF·Docs/Word·Excel·시트의 추가 실제 파일 입출력 조합은 미정이며 파일별 지원을 주장하지 않는다. 배포된 것은 질문·뉴스의 정적 mock 화면뿐이고, 유료 수집·Ralph 실행은 하지 않는다.
- 질문 게시판과 별도 뉴스 카테고리에서 AI 소식과 업무 도구 추천을 잇는 화면은 이번 mock 시연 범위다. 실제 게시글 저장·계정·공개 범위, 한국어 Threads 자동 수집, 실제 뉴스 공급원, 제품별 계정·요금·파일 형식·기업 정책 검증은 다음 연동 범위다.

작업 지침은 [AGENTS.md](AGENTS.md)에 있다. 비밀키와 로그인 정보는 저장소에 넣지 않는다.
